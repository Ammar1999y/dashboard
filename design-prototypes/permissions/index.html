Permission matrix prototype

The matrix component shared by the permission form and the user form's “مخصص” role. It is self-contained and runs against an in-memory mock of the real role rules. A dev bar switches between create and edit, sets the current user's grants, shows the request payload, and runs the save flow.

Vanilla JS · dashboard tokensشبكة ذكية

Pages × verbs (not 9 raw columns) with scope chips, a progress bar per page, tri-state row and column controls, dependency highlighting, a plain-language line per page and full keyboard control.

Problems in today's matrix that it fixes

  • A sparse 9-column grid. 13 of 36 cells are blank, and long labels force sideways scrolling.
  • Duplicated actions. “All” and “own” are separate checkboxes, so both can be ticked even though “all” already covers “own”. Each verb is now one choice: none / own / all.
  • Toggle buttons that mislead. Every row and column button says “اختيار الكل”, even when clicking it will clear.
  • Silent changes. Unticking view quietly removes edit, delete and publish. Now every automatic change is announced and can be undone.
  • New roles start with full access. They now start empty, with templates to choose from.
  • Ungrantable options look available. The server refuses anything you don't hold yourself, but today's form shows those options as normal. Now they are locked with the reason shown.
  • Grant errors only in a toast. A refused grant is now marked on the cell that caused it.
