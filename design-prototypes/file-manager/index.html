Media library prototype

Self-contained and runs against an in-memory mock that applies the real back-end rules. Features marked ✦ / “يتطلب دعم الخادم” are not supported by the back end yet; “إظهار الميزات المستقبلية” in the ⋯ menu hides them.

Finder column view with an inspector column, dense grid and list views, path bar, cut & paste moving, ⌘K command palette, keyboard-first, dark-first.

What the back end supports today

CapabilityStatusNotes
Nested folders: create, rename, moveSupportedDepth 10, 500 children per parent, names unique per parent (case-insensitive).
BreadcrumbsSupportedReturned with every folder listing and folder search hit.
UploadPartialOne file per request, so multi-upload is a client queue. 20 req/min, encoder queue of 4 (503 when full). Images ≤ 1 MB, documents ≤ 10 MB.
Allowed typesPartialThe server stores PNG, WebP, SVG (strict), PDF, DOCX and XLSX. JPEG and HEIC/HEIF are accepted by the dashboard, which converts them in the browser to WebP under 1 MB before upload. GIF, video, audio and ZIP are refused. PNG and WebP are stored as WebP.
Rename fileSupportedDisplay name only.
Move many filesSupportedUp to 50 ids, all or nothing. Files only, never to the root.
Delete many filesSupportedUp to 50 ids, always permanent.
Delete folderPartialEmpty only, or recursive up to 200 descendants. One folder per request.
Publish / unpublishPartialOne file per call, 10 per minute.
SearchPartialMatches file names only, 3+ characters; shorter terms are silently ignored. Folder-name search returns the top 20, in “all” scope only.
Sort and filterPartialFiles: name, size, type, kind, visibility, created, updated. Folders: name only. No filter by uploader.
PaginationSupportedOffset paging, up to 100 per page, with a total count.
Details, download, “where used”PartialDownload link is valid for 1 hour and comes from the details call only. “Where used” always returns nothing today because no table references files yet.

Missing in the back end (shown as ✦ in the prototype)

Trash, favourites, recent, and alt text / tags / caption are out of scope by owner decision and not shown in the prototype.

FeatureStatusWhat it would take
Files in the rootMissing (by design)Every file must be in a folder, so dropping at the root asks for a folder first.
Move folders in bulk / mixed selectionsMissingThe client loops one request per folder. A bulk endpoint that accepts folder ids would make this all-or-nothing.
Bulk delete foldersMissingSame as above.
Bulk publish / unpublishMissingLooping hits the 10/min limit after 10 files.
Folder tree in one callMissingThe tree loads one level per request.
Item count / size per folderMissingAggregate columns in the listing.
Storage usage / quotaMissingsum(size_bytes) endpoint.
Thumbnails / image variantsMissingGrids load full images. Private URLs are re-signed on every listing and sent no-store, so thumbnails never cache.
PDF / document previewMissingDocuments are always served as downloads.
Search a folder including its subfoldersMissingSearching inside a folder only matches the files directly in it; the whole library is the other option.
Copy / duplicateMissingAn R2 copy helper already exists (used by publish).
ZIP download of several filesMissingStreaming zip endpoint.
Share link with expiryMissingThe only options are fully public or a private 1-hour signed URL.
Replace file / versionsMissing (by design)—
Duplicate detectionMissingsha256 is stored but unused.
Uploader name / avatarPartialOnly a user id is returned.
Machine error codesPartialMedia errors are an HTTP status plus Arabic text, with no code, so the UI cannot branch on error type.
Realtime updatesMissingChanges by other users show up only after a refetch.
Chunked / resumable uploadMissingThe server buffers the whole body.
