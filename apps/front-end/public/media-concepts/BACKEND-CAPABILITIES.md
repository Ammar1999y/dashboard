# Media manager: backend capabilities and integration notes

Source audit: 6 October 2026. This report describes the checked-in implementation, not a live deployment. No backend requests, database mutations or application UI tests were run. The concepts use local sample data; their counts describe that sample.

**The backend already supports moving multiple files.** A Drive-style grid, multi-selection, keyboard shortcuts and dragging selected files into folders can use existing contracts. The list endpoint's use of data-table query parameters does not require a table interface.

## Data, search and permissions

Files expose `id`, `kind` (image/document), `displayName`, MIME type, byte size, public/private `bucketType`, nullable processing `transition`, dimensions/blurhash, `folderId`, uploader ID, `unfiledAt`, URL and timestamps. Details add download and usage information. Folder summaries expose IDs, name, parent/creator IDs and timestamps. **No folder counts, aggregate sizes, owner display names, favorites, colors, tags, quota totals or activity feed are supplied.** [File shape](../../../back-end/lib/media/files.ts:230), [folder shape](../../../back-end/lib/media/folders.ts:23).

Search matches display names; quick search requires 3–200 characters and an indexable letter/number pattern. Short/long/non-indexable quick searches are silently ignored, so the UI should explain the minimum length. Match the shared `effectiveSearchTerm` helper: it strips controls, measures Unicode code points before case conversion, and applies its trigram boundary rules. Filters and sorting support name, size, MIME type, image/document kind, visibility, created and modified dates. Unknown/invalid filters produce 422; unknown sort IDs fall back to valid/default sorting. Files default to newest first, 10 per page, maximum 100; folders are alphabetic and unpaginated. Existing type filters include disabled historical DOC/XLS types. [Search normalization](../../../../packages/shared/src/data-table/parsers.ts:155), [filter contract](../../../../packages/shared/src/data-table/filterable-columns.ts:33), [query parsing](../../../back-end/lib/data-table/params.ts:49), [bounds](../../../../packages/shared/src/data-table/parsers.ts:387).

The media permissions are `view`, `create`, `edit`, `editOwn`, `delete`, `deleteOwn`, `publish`. View sees the shared library; there is no view-own or per-folder sharing ACL. Own-edit/delete means uploader for files and creator for folders, including every item inside recursive deletion. Inaccessible mutations return 404. Create covers uploads and folders. Publish has no own variant. [Permission definitions](../../../../packages/shared/src/permissions/constants.ts:154), [ownership scope](../../../back-end/lib/media/actor.ts:60).

Folder names are unique among siblings without regard to case, maximum 100 characters; file display names allow 150. Names normalize Unicode/whitespace and reject controls and path separators. Folder depth is capped at 10 and each parent/root at 500 child folders. File names need not be unique, and upload does not detect duplicates. [Validation](../../../../packages/shared/src/validation/media.ts:78), [folder constraints](../../../back-end/db/schema.ts:639), [limits](../../../../packages/shared/src/validation/constants.ts:20).

## Uploads, previews and access

- **Server accepts:** PNG, WebP, SVG, PDF, DOCX, XLSX. DOC/XLS are implemented but disabled. JPEG/HEIC/HEIF conversion belongs to the existing frontend preparation pipeline; the server rejects those formats directly. GIF/animation, video/audio, archives and generic files are outside the allowlist. [Allowlist](../../../../packages/shared/src/validation/media-types.ts:26), [frontend conversions](../../lib/files/accept.ts:34).
- **Limits:** raster input up to 1 MiB, document input 10 MiB; 25 megapixels and 16,383 pixels per side. SVG has an additional 0.4 MiB ceiling, 500 elements and bounded attribute/rendered-node counts. Content is inspected, including Office package checks; macros, embedded objects and encrypted Office containers are rejected. [Shared limits](../../../../packages/shared/src/validation/constants.ts:6), [SVG limits](../../../../packages/shared/src/images/config.ts:34), [admission](../../../back-end/lib/media/upload.ts:221).
- Raster images are re-encoded to WebP, with a 0.2 MiB target and **800 KiB fallback ceiling** if the target cannot be reached. The longest edge starts at up to 3,048 pixels and can shrink further. The stored raster gets dimensions and a nullable blurhash. Sanitized SVG remains SVG with null dimensions/blurhash. The old backend user guide's hard 200 KB claim is stale. [Optimizer](../../../back-end/lib/media/image/optimize.ts:162), [processing](../../../back-end/lib/media/image/process.ts:143).
- Image preview can use the file URL and blurhash; there is no separate thumbnail or resolution-variant endpoint. Documents are served as attachments, including PDF: the current contract provides download and metadata rather than inline document preview. [Response headers](../../../back-end/lib/media/headers.ts:73).
- Private viewing URLs expire after one hour. Signed download URLs also expire, including downloads of public files, and carry the current filename. Public viewing URLs are permanent when a public domain is configured; rename/move do not alter their object key. Otherwise the server returns a signed URL. A private link is a temporary bearer link, not an invitation/share ACL. Refresh file details/listings for fresh URLs. [URLs](../../../back-end/lib/media/files.ts:269), [expiry](../../../back-end/lib/r2/client.ts:26).
- Upload admission: 20 attempts/minute/user shared across upload routes, plus a 100-megapixel image budget (minimum charge 5/request) and 60 MiB document budget (minimum charge 2/request). Standard media writes have separate 30/minute route scopes. Publish/unpublish share 10/minute. Lists/details have separate 120/minute scopes. Queues should respect `Retry-After`. [Upload budgets](../../../back-end/lib/media/upload.ts:51), [admission cap](../../../back-end/lib/media/upload.ts:522).

## Lifecycle and blockers

There is **no recycle bin, restore or undo**. References from registered content prevent deletion; public references prevent unpublishing. Busy transitions (`to_public`, `to_private`, `cleanup`) block competing writes. Delete success may mean storage cleanup is pending. Cached public image copies can outlive an unpublish/delete; the public response caches images for a year. [Lifecycle](../../../back-end/lib/media/lifecycle.ts:194), [visibility](../../../back-end/lib/media/visibility.ts:173), [headers](../../../back-end/lib/media/headers.ts:14).

The separate `/api/upload/file?resource=<page>&purpose=<name>` route is for record forms: one multipart `files` field, pending until claimed, cleanup after 24 hours. Registered record files are managed through their owning records. Orphans enter unfiled retention for seven days from the maintenance sweep's first stamp; moving into a folder clears the clock. **This starter currently registers no named upload purposes or usage sources.** Its safe `unreferenced()` default is false, making unfiled listing/reaping dormant and `usedBy` empty. The concepts show an explanatory empty state for unfiled files. [Record route](../../../back-end/app/api/upload/file/handler.ts:61), [retention](../../../back-end/lib/media/lifecycle.ts:39), [empty registry](../../../back-end/lib/media/usage-sources.ts:37), [safe default](../../../back-end/lib/media/usages.ts:137).

## Gaps and integration priorities

| Priority                      | Feature                                                                                                                                                       | What is needed                                                                                                                                                                                                           |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Implement in frontend now     | Grid/gallery/column navigation, file range selection, marquee selection, keyboard shortcuts, context menus, file drag-to-folder, multi-file drop/upload queue | Existing list/move/upload contracts. Cap each atomic file selection at 50; paginate honestly. Folder drag can use its single-item move. Recent/image/document/public/private views can use existing sort/filter options. |
| Highest backend improvement   | Atomic mixed file/folder and multi-folder moves/deletes                                                                                                       | New bulk contracts; today folders require separate requests with possible partial results. Bulk publish can be queued via existing requests, but lacks atomicity and has the 10/minute cap.                              |
| Product decision              | Root-level files, recycle bin/restore, copy/duplicate, replace/version history                                                                                | Schema/lifecycle/API work. Existing backend guide explicitly treats root files, recycle bin and versioning as prior exclusions; revisit those choices before promising them.                                             |
| Workflow improvement          | PDF/Office preview, directory upload, bulk ZIP download, resumable large uploads                                                                              | New supported delivery/processing or queue contracts. Browser orchestration is possible for repeated uploads/downloads, but is not an atomic backend batch and remains rate limited.                                     |
| Optional organization/sharing | Favorites, tags, folder counts/size, quota, per-user sharing/invitations, expiring guest links, change history                                                | New fields, indexes, permission/delivery contracts. Local prototype sample counts are not server totals.                                                                                                                 |

When applying a chosen design, retain the current page entry and authorization boundary, and reuse existing API/schema/cache/mutation/upload modules. Replace the table presentation in [library-view.tsx](../../components/dash/media/library-view.tsx:79); its query-state source currently comes from the table store. [queries.ts](../../lib/media/queries.ts:14) already accepts the shared query shape, [actions.ts](../../lib/media/actions.ts:63) handles mutations/cache updates, and [upload.ts](../../lib/media/upload.ts:31) handles conversion/retry. Extend the selection store for range/marquee behavior; it currently keeps **only selectable files on the current page**, capped at 50, and clears across page/folder changes. Preserve this scope explicitly or redesign it deliberately. [Selection](../../lib/media/selection.ts:7), [access](../../components/dash/media/access.ts:12).

Prototype verification is separate from backend verification. This audit traced handlers, schemas, services, storage headers and integration-test cases; it did not establish that a deployed server's migrations, storage configuration, permission grants or maintenance schedule are active.
