# Mock API

Answers every backend request in the browser with [MSW](https://mswjs.io), so the dashboard runs without the back-end.

Mocking is decided when the app is built, by `NEXT_PUBLIC_API_MOCKING=enabled`:

```sh
bun run build   # this repo's build script sets the flag
bun run start

bun run dev:mock   # the same, in development
```

A build without the flag contains no mock code and keeps the full production CSP.

Any email and password signs in. A seeded email (`admin@gmail.com`, `user1@gmail.com` … `user22@gmail.com`) signs in as that user; any other email creates a full-access user on the spot. The form's own rules still apply first (a Gmail/Outlook/Hotmail/Yahoo address, and a password with upper case, lower case, a digit and a symbol). To test a refused sign-in, run `mockApi.fail('/api/auth/sign-in/email', 401)`.

A mock build also changes two files outside `mocks/`, both keyed on the same flag:

- `next.config.js`: the CSP drops `upgrade-insecure-requests` (it would turn the `http` API URL into an `https` one that `connect-src` refuses) and allows `https://challenges.cloudflare.com` in `connect-src` (the service worker re-fetches the Turnstile script under that directive). `env` inlines the flag even when unset, so a normal build can drop the mock chunk.
- `components/sign-in/turnstile.tsx`: uses Cloudflare's always-pass test key, because the real key is refused on localhost.

## How it hooks in

- `pages/_app.tsx` exports `withApiMocking(App)`. It holds the first render until the service worker (`public/mockServiceWorker.js`, generated by `msw init`) is running.
- Handlers match the same URLs `apiFetch` and the better-auth client call (`API_URL` + path). Nothing in `utils/query.ts`, `utils/mutation.ts` or `lib/api.ts` knows mocking exists.
- Data is seeded from `seed.ts` and saved in `localStorage` under `mock-api:v1:*`, so creates, edits, deletes and the signed-in session survive a reload.

## Layout

| Path                      | What it holds                                                    |
| ------------------------- | ---------------------------------------------------------------- |
| `handlers/auth.ts`        | `get-session`, `sign-in/email`, `sign-out`, `/api/dev/sign-up`   |
| `handlers/users.ts`       | users list (server-paged), detail, create, update, delete        |
| `handlers/permissions.ts` | roles picker, permissions list (server-paged) and CRUD           |
| `handlers/content.ts`     | projects, categories, sections, settings, `/api/upload`          |
| `lib/data-table.ts`       | paging, sort, search and filters for `useServerDataTable` tables |
| `lib/crud.ts`             | list/detail/create/update/delete for tables loaded whole         |
| `store.ts`, `seed.ts`     | the tables and their starting rows                               |

To mock a new endpoint, add a handler next to its neighbours. A resource whose list is loaded whole can usually be covered by one `crud(path, table)` line.

## Testing UI states from the browser console

```js
mockApi.fail('/api/dash/users', 500); // every method on that path returns 500
mockApi.fail('/api/dash/users/:id', 422, 'رسالة'); // custom status and message
mockApi.offline('/api/dash/projects'); // network error
mockApi.latency(3000); // slow every request
mockApi.restore(); // undo the overrides above
mockApi.reset(); // back to seed data, signed out
```

Overrides live in the page, so they are lost on a full reload. Set one, then navigate inside the app.

## Removing it

Delete `mocks/` and `public/mockServiceWorker.js`, revert `withApiMocking` in `pages/_app.tsx`, and remove the flag from the `build` script, the `dev:mock` script, the `msw` dev dependency and the `msw` block from `package.json`. Then drop the `isApiMocking` lines from `next.config.js`, the flag check in `components/sign-in/turnstile.tsx`, and `public/mockServiceWorker.js` from `eslint.config.mjs` and `.prettierignore`.
