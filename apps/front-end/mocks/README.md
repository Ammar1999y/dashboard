# Mock API

Answers every backend request in the browser with [MSW](https://mswjs.io), so the dashboard runs without the back-end.

Mocking is decided when the app is built, by `NEXT_PUBLIC_API_MOCKING=enabled` in the environment or `.env`:

```sh
bun run build:mock   # sets the flag; `bun run build` reads it from the environment
bun run start:mock   # `next start` reads the config again, so it needs the flag too

bun run dev:mock     # the same, in development
```

A build without the flag contains no mock code. A mock build needs no `.env`: it sends every API request to `https://api.mock.invalid`, which the handlers answer, so a request they miss fails instead of reaching a server with real data. If the service worker cannot start, or the browser lacks `crypto.randomUUID` (which it needs for every request), the app shows an error rather than starting without it.

Any password signs in. A seeded email (`admin@gmail.com`, `user1@gmail.com` … `user22@gmail.com`) signs in as that user, refused as the server refuses it: a deactivated account, a deactivated role or no role answers 401. Any other email creates a full-access user on the spot. Each user gets what their role grants, as on the server: `user1@gmail.com` is an editor (no deletes, no roles page), and the members of the deactivated `مشاهد` role cannot sign in. A role or account deactivated while its user is signed in ends that session. The form's own rules still apply first (a Gmail/Outlook/Hotmail/Yahoo address, and a password with upper case, lower case, a digit and a symbol). To test a refused sign-in, run `mockApi.fail('/api/auth/sign-in/email', 401)`.

A mock build also changes two files outside `mocks/`, both keyed on the same flag:

- `next.config.js`: `env` inlines the flag even when unset, so a normal build can drop the mock chunk. Its CSP has mock-build changes too (no `upgrade-insecure-requests`, and `https://challenges.cloudflare.com` in `connect-src`, under which the service worker re-fetches the Turnstile script), but no CSP is sent while `headers` is disabled there.
- `components/dash/auth/turnstile.tsx`: uses Cloudflare's always-pass test key, because the real key is refused on localhost.

## How it hooks in

- `pages/_app.tsx` exports `withApiMocking(App)`. It holds the first render until the service worker (`public/mockServiceWorker.js`, generated by `msw init`) is running.
- Handlers match the same URLs `apiFetch` and the better-auth client call (`API_URL` + path). Nothing in `lib/api/` or `lib/files/` knows mocking exists.
- They follow the server's contract: bodies are parsed with the schemas the server uses (`@app/shared/contract` for users, roles and auth), statuses and messages are the server's (`@app/shared/messages/*`, `@app/shared/http-status`, `@app/shared/error-codes`), and the checks run in the server's order. `lib/permissions.ts` is the server's permission gate over the signed-in user's role: 401 for an inactive account, 403 for an inactive role or a missing grant, and the `own` scope of `viewOwn`/`editOwn`/`deleteOwn`, which reaches only the rows the user created (`createdBy`). The rules over the matrix itself (resolving a scope, refusing to grant more than the actor holds) are the server's own code, in `@app/shared/permissions/*`.
- A handler that throws answers the API envelope, as the server's `withApiErrors` does: `handlers/index.ts` wraps every handler at registration, so a new module needs nothing.
- Data is seeded from `seed.ts` and saved in `localStorage` under `mock-api:v<SEED_VERSION>:*`, so creates, edits, deletes and the signed-in session survive a reload. Bump `SEED_VERSION` when a seeded shape changes; keys saved under another version are deleted at startup. Another tab's writes are picked up on the next request. A write the browser refuses (a full quota) fails its request.

## Pending back-end

Settings has no back-end route yet. `handlers/content.ts` is its only implementation; it parses the body with the form's own schema, as its route will. Settings is one row, upserted whole: every save answers 200. When the route ships with the same contract, delete its handler: the front-end needs no change.

## Layout

| Path                      | What it holds                                                     |
| ------------------------- | ----------------------------------------------------------------- |
| `handlers/auth.ts`        | `get-session`, `sign-in/email`, `sign-out`, `/api/dev/sign-up`    |
| `handlers/users.ts`       | users list (server-paged), detail, create, update, delete         |
| `handlers/permissions.ts` | roles picker, permissions list (server-paged) and CRUD            |
| `handlers/content.ts`     | settings (no back-end yet)                                        |
| `handlers/media.ts`       | `POST /api/upload/file`, as the server admits files               |
| `lib/data-table.ts`       | paging, sort, search and filters for `useServerDataTable` tables  |
| `lib/http.ts`             | the envelope, body and id parsing, the error wrapper              |
| `lib/messages.ts`         | refusals of the pending entities, which the server has no copy of |
| `store.ts`, `seed.ts`     | the tables and their starting rows                                |

To mock a new endpoint, add a handler next to its neighbours.

`tests/mocks-*.test.ts` run the real handlers under `msw/node` (`tests/mocks-harness.ts`); `bun test tests/mocks-users.test.ts` runs one.

## Testing UI states from the browser console

```js
mockApi.fail('/api/dash/users', 500); // every method on that path returns 500
mockApi.fail('/api/dash/users/:id', 422, 'رسالة'); // custom status and message
mockApi.offline('/api/dash/settings'); // network error
mockApi.latency(3000); // slow every request
mockApi.restore(); // undo the overrides above
mockApi.reset(); // back to seed data, signed out
```

Overrides live in the page, so they are lost on a full reload. Set one, then navigate inside the app.

## Removing it

Delete `mocks/`, `public/mockServiceWorker.js`, `tests/mocks-*` and `tests/fixtures/_mock-storage-child.ts`, revert `withApiMocking` in `pages/_app.tsx`, and remove the `build:mock`, `prebuild:mock`, `start:mock` and `dev:mock` scripts, the `msw` dev dependency and the `msw` block from `package.json`. Then drop the `isApiMocking` lines from `next.config.js` and `lib/env.js`, the flag check in `components/dash/auth/turnstile.tsx`, and `public/mockServiceWorker.js` from `eslint.config.mjs` and `.prettierignore`.
